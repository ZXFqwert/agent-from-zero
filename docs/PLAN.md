# 学习方案

## 目标与教学方式

最终做出一个能在指定工作目录读取文件、提出修改、经确认写入并执行验证命令的命令行 Agent。学习者应能独立解释消息历史、工具协议、执行循环和会话恢复。

采用 Python，先使用标准库和必要的模型 SDK，不使用 Agent 框架封装核心循环。每次学习约 30–60 分钟，按实际理解程度调整：解释一个概念 → 学习者写一小段 → 运行观察 → 复述原理 → 更新进度并提交。用户明确要求代写时可以代写，但要讲清关键逻辑。

## 阶段与验收

| 阶段 | 要学与要做 | 验收标准 | 状态 |
| --- | --- | --- | --- |
| S0 起点 | 方案、进度、Git、GitHub | 文档可接续，本地与远端提交一致 | 已完成 |
| S1 模型调用 | 消息角色、一次请求、响应、环境变量 | 发出一次真实请求并解释输入输出；缺配置时提示明确 | 进行中：消息列表练习已运行 |
| S2 多轮聊天 | 保存消息历史、命令行输入、退出 | 模型能回答基于上一轮的问题 | 待开始 |
| S3 第一个工具 | 工具名称、参数 schema、调用 ID、结果 | 模型请求 read_file，程序执行并回传，模型基于结果回答 | 待开始 |
| S4 Agent 循环 | 多次工具调用、结束条件、错误反馈 | 自动完成“读两个文件并比较”，有最大步数限制 | 待开始 |
| S5 编程工具 | write_file、edit_file、run_command | 在练习目录修改文件并运行验证；写入与命令执行需确认 | 待开始 |
| S6 会话持久化 | JSONL、恢复、模型历史与显示记录 | 重启后继续会话，工具调用与结果配对完整 | 待开始 |
| S7 交互与可靠性 | 流式输出、中断、超时、工具日志 | 可取消请求，错误可理解，日志不含密钥 | 待开始 |
| S8 扩展与收尾 | 项目指令、工具注册、上下文整理 | 新增工具无需改循环，通过一个完整修复任务 | 待开始 |

第一版完成线是 S5：能读代码、改代码、验证结果。会话和 UI 在核心循环稳定后加入。多 Agent、RAG、浏览器和复杂 TUI 留作后续选题。

## 借鉴 Pi 的方式

Pi 的核心分层为本项目提供阅读线索，我们按学习需要逐步拆文件，以下均为规划，尚未实现：

| 参考关注点 | 本项目计划文件 | 责任 |
| --- | --- | --- |
| 模型接口 | mini_agent/llm.py | 请求与响应转换 |
| Agent Core | mini_agent/loop.py | 消息追加、工具调度、终止 |
| Coding Agent 工具 | mini_agent/tools.py | 文件读写与命令执行 |
| 会话 | mini_agent/session.py | 保存和恢复 |
| 终端入口 | mini_agent/cli.py | 用户输入、输出与确认 |

```text
用户输入 → 加入消息历史 → 调用模型
                            ├─ 最终回答 → 显示并结束本轮
                            └─ 工具请求 → 校验参数与权限 → 执行工具
                                              └─ 结果加入历史 → 再调用模型
```

先用一个文件理解过程，再在职责清楚时拆分。Pi 的 `bash` 在本项目先实现为明确使用 PowerShell 的 `run_command`。

## 验证和边界

- 工具只操作明确的练习工作目录；检查绝对路径、`..` 和符号链接/重解析点越界。
- 写文件和执行命令先显示具体内容或命令，由用户确认；命令设置超时和输出上限。
- S4 起用假模型响应验证循环的完成、未知工具、异常和最大步数，不消耗真实模型额度。
- 真实模型验证单独记录，不能用模拟结果代替真实接口验收。
- 每次只提交当前学习范围内的改动；密钥、会话和本地配置不进入 Git。
