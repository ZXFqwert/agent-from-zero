## 玩法承诺与比较口径

七件城市遗物分别映射一种系统设计。每组第一场让玩家亲手利用设计完成任务；第二场让相同设计遇到信息缺口、资源、信任或兼容约束。两场后才完整揭示现实名称与来源；随时可以从资料入口提前查看，不设置答题门禁。

所有策略都是明确标识的教学模拟。这里不运行七套产品，不比较真实模型聪明程度、生成速度或价格；不使用品牌攻击力、智力等级与安全率。模型、上下文、工具、权限、调度、存储和验收是相互影响的系统部分，多个产品都具备其中多种能力。本组只是挑出便于学习的设计切面，不是独占能力清单。

同一比较台保留一个运输锚点：“把已授权的箱子送到指定人，保留应急库存，按真实收件验收”。地图、箱数、原始材料、法器费用与完成条件可固定；玩家一次只改变一个声明配置，比较实际轨迹。十四场本身有不同事故和决策，不能复制锚点换品牌文案。使用不同模型适配器时，它们是 A / B 两种有限策略，不把预设好坏冠以真实型号。

| 比较轴 | 玩家实际能检查的证据 | 不作的推导 |
|---|---|---|
| 执行边界 | 请求目标、执行环境、批准绑定、实际拒绝与副作用 | 有审批按钮就等于任何代码都安全 |
| 当前知识 | 本轮已带字段、摘要省略、私有输入和来源 | 磁盘存在就等于模型当前看见 |
| 延续方式 | 会话、外部记忆快照、技能适用条件、持久事件 | 保存经验就等于更新模型权重 |
| 调度与交接 | 原始寄件身份、会话键、任务编号、队列和回执 | 更多入口或伙伴必然更聪明 |
| 可配置范围 | 模型适配、角色、权限或插件的实际独立变更 | 换模型会自动修好工具与授权 |
| 成本与验收 | 实际调用、共同晶石、已测分母、现场完成状态 | 这组小案例证明品牌整体强弱 |

成功反馈来自世界变化和工具证据：门打开、货箱移动、信件进正确抽屉、错误共享停止、日志能恢复。知识卡放在复盘，不把读完卡或选择产品名当成过关。允许第一次就正确；每场同时编写无错误参考路线、典型错误后的恢复路线，必要时加真正可达的替代解。

### Codex：执行边界与请求批准

- 文档版本：官方在线文档，2026-10-03 核查；未绑定 Codex CLI / 桌面构建版本。[Agent approvals & security](https://learn.chatgpt.com/docs/agent-approvals-security)
- 已核事实：沙箱限制动作技术上可触及的范围，批准策略决定何时要求审阅；不同执行环境有不同配置。工作区允许的常规动作可以持续执行，扩大范围需要相应授权，具体默认依环境核对。
- 游戏简化：虚拟工作区、固定法器请求和一次许可；不复制真实 OS 沙箱、网络代理、自动审批审查器或全部云端政策。v7 的“试验副本”不能被描述成 Codex 的 OS 沙箱原样实现。
- 两场体验重点：将准备、执行与交付证据分开；在足够权限和过宽授权之间进行具体范围选择。其他产品也能实现工作区、审批与隔离。

### Claude Code：信息组织与专项委托

- 文档版本：官方在线工作方式与子代理文档，2026-10-03 核查，未把正文示例版本当成当前完整产品版本。[How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works)、[Create custom subagents](https://code.claude.com/docs/en/sub-agents)

- 游戏简化：有限容量和作者声明的摘要、专项任务及报告；不复现自然语言摘要质量、模型内部思考、真实 token 计数或模型计费。
- 两场体验重点：专项调查降低主上下文负担；摘要和共同来源可能损失重要细节，最终验收仍需主任务负责者。

### OpenClaw：入口、会话与队列

- 源码提交：`dd66b67807344d7754de8f7bc29af7c9e9e59bf7`；文档源 `doc-schema-version: 1`。[Session management](https://github.com/openclaw/openclaw/blob/dd66b67807344d7754de8f7bc29af7c9e9e59bf7/docs/concepts/session.md)、[Command queue](https://github.com/openclaw/openclaw/blob/dd66b67807344d7754de8f7bc29af7c9e9e59bf7/docs/concepts/queue.md)
- 已核事实：会话分组由宿主配置决定；DM 的 main 与按发送者/渠道隔离解决不同需求。每会话队列避免同一会话并发写入；followup、collect、interrupt、steer 有不同含义，队列不将输入升级为另一位发送者的权限。
- 游戏简化：三种虚拟入口、有限寄件身份与逻辑轮；不是接入真实聊天平台，也不以固定游戏并发数宣称产品默认并发。运行中法器与尚未发出的法器分开，不能把改口当成撤销已发生的动作。
- 两场体验重点：路由与身份不是由模型自由猜测；连续消息、忙碌和取消需要明确制度。长期记忆不是它独有的能力。

### Hermes Agent：跨会话经验与适用性

- 仓库 HEAD：`eb7e8620324b32424c06218f6a28094df2e921f8`，只作源码核查定位；在线文档版本为 2026-10-03 快照。[Architecture](https://hermes-agent.nousresearch.com/docs/developer-guide/architecture)、[Persistent Memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory/)、[Skills System](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)、[官方仓库快照](https://github.com/NousResearch/hermes-agent/blob/eb7e8620324b32424c06218f6a28094df2e921f8/README.md)
- 已核事实：小型持久记忆与长程序技能分工；内置记忆以会话开始时的冻结快照进入系统提示，实际写入即时持久化，但不原地改写已有会话的该提示块。技能可由 Agent 创建与修订，历史会话另有存储与检索。
- 游戏简化：只有少量有版本的事实、流程和会话快照；不自动生成技能，不模拟所有外部记忆提供方、真实检索质量或权重训练。游戏让玩家审阅经验，不以自称“学会了”代替真实保存与成功复用。
- 两场体验重点：把一次成功保存为后续适用的流程；发现旧经验失效后修订，并看清磁盘新版本与当前快照的差别。

### OpenCode：模型、工作角色与权限独立配置

- 文档版本：官方 V2 文档，2026-10-03 核查。[Agents](https://opencode.ai/v2/docs/agents)、[Providers](https://opencode.ai/v2/docs/providers)、[Permissions](https://opencode.ai/v2/docs/permissions)、[Migrate from V1](https://opencode.ai/v2/docs/migrate-v1)

- 游戏简化：两种虚拟连接、有限角色和三值权限规则；不是完整 V1/V2 配置解释器或真实模型比较。不得将“切换主角色”动画自动视为会话模型已切换，也不能概括为 V1 配置全部失效。

## 逐场可实施玩法

以下是原创教学情境，而非官方产品流程或某品牌必然失败的描述。每场最后用同一个复盘结构：故事后果 → 信息 / 执行 / 证据流 → 现实参考与简化边界。社会类比说明制度分工，不给模型安排贪婪、忠诚或稳定自我目标。

### C1 · 围墙里的灯

莫拉要修码头信号灯，居民库房与灯台共享一条巷道。开始一分钟内，玩家把观察法器指向灯台，实际取得断路信息；工作区只含灯台和维修台。

- 玩家操作：限定可写目标 → 用观察取得接线方案 → 在独立试验副本接线并验收 → 核验岗位，预览并批准该次现场接线 → 真实点灯、复查并交付。
- 因果与证据：读资料不会点亮灯；批准的固定请求不能替另一个目标开门，试验副本的亮灯也不会复制到现场。胜利需要现场成功调用、有效批准及新验收。
- 错误与恢复：仅在试验副本完成就尝试交付，门槛拒绝；保留试验记录，回现场核对请求和条件后实际施工。首次正确路线直接可通，不先破坏居民库房。
- 复用与边界：v8 可继承 v7 身份、单次批准与分域世界；工作区是虚拟目标范围，并非真实目录沙箱。社会映射是授权和技术隔离承担不同责任。

### C2 · 门令与围墙

岑只授权修公共闸门，维修卷轴附带“顺便开启储备库”的指示。玩家先实际预览两种不同目标，决定可持续自动执行的常规范围与必须审阅的越界请求。

- 玩家操作：配置窄范围 → 对闸门请求签单次许可 → 执行并查看许可消耗 → 尝试把同一许可用于库门或改目标，看到无副作用拒绝 → 从正确岗位和明确委托核对是否应扩大范围。
- 因果与证据：范围扩大可以减少后续打断，但真实开放更多虚拟目标；关闭审批提示不会让隔离范围自行扩大，隔离也不替玩家判断委托是否授权。规定目标完成、库存保持、拒绝事件与实际访问范围共同验收。
- 错误与恢复：已经选择广范围且开放储备库时，要真实关闭库门、复查库存，再重新配置最小范围；改契约不能撤销已发生的开门。可从开始就用窄权限完成。
- 复用与边界：固定审批可用 v8；若让玩家独立配置虚拟工作区与批准策略，需新增两个不同字段，不以现有 `permissions` 一字段同时扮演两层。复盘不声称真实 Codex 必会服从卷轴。

### A1 · 把调查交出去

阿芙交出八份洪水记录，主卷轴只容四格。玩家的第一个动作是选一项“勘测最低桥墩”的专项任务，把真正取得的水位记录交给弥灯，而非复制整本历史。

- 玩家操作：给专项伙伴设置只读勘测能力和私有输入 → 排队执行 → 按原任务号接回所需桥墩数据 → 装入主卷轴 → 主任务执行加固并验证。
- 因果与证据：伙伴报告既不自动进入主上下文，也不给它施工岗位。主上下文不会被调查日志挤满，但实际工具、成本与返回字段均可检查。
- 错误与恢复：派出空输入的任务得到明确缺字段停止；交回后未装卷则主策略缺信息。补实际材料、新建任务、正确接回与装卷后可继续原委托。依赖仍绑定具体实例。
- 复用与边界：v8 私有任务、权限和有限资料可直接承载。游戏选择普通独立上下文路径，复盘同时提示现实产品也有 fork；不得把两个伙伴描述成 Claude 模型的内部模块。

### A2 · 短报告，长裂缝

鲁因要修一座潮水中会膨胀的桥。两份短报告都写“尺寸合适”，其中一份摘要省掉涨潮刻度，另一份保留刻度、时间和来源。

- 玩家操作：比较自己实际读到的材料 → 选择摘要保留字段或回原记录 → 把足够证据交给施工伙伴 → 在晴潮、满潮两案例分别运行当前构筑 → 集成并现场检验。
- 因果与证据：被省掉的字段不能因报告更短或多招一位伙伴重新出现；两份同源报告不增加独立证据。两种案例的工具结果与当前版本检查决定资格，施工决定现场。
- 错误与恢复：丢关键字段的短报告在明确物理边界下失败；重读或换保留摘要、重新派遣与量测，不给队友隐形共享全部档案。可以首次使用完整证据而无需失败。
- 复用与边界：v8 摘要 / 来源 / 交接与 v9 案例评价可组合于新关卡内核；是否允许组合须实际验证，不认为已有模块单独通过就自动组合正确。社会映射是汇报压缩与组织共同盲点。

### O1 · 三只收信鸦

莫拉的港口、缇娅的药棚和居民访客共用一个邮亭；两人显示姓名相同。玩家先投递一封已认证港口来信，看它实际进入哪个抽屉。

- 玩家操作：用真实寄件 ID、入口和账号配置路由 → 选择按寄件人或入口＋寄件人分会话 → 对自己的两个入口明确建立身份关联 → 发送有限虚拟来信 → 查看分别携带的资料和真实回复地址。
- 因果与证据：显示姓名不用于认证；路由由宿主契约确定，正文“我是港务长”不能改写源身份。会话隔离控制可见历史，岗位权限另行检查，回信送达正确人才能验收。
- 错误与恢复：把不同人汇入 main 抽屉，测试显示不该共享的药棚字段；暂停该路由、建立隔离抽屉，再让未处理请求进入新键。已暴露材料保留在事件中，不能靠改设置声称从未共享。
- 需新增：真实有限路由与逐会话上下文合同。现有 `session.fresh/fork` 不是多入口身份路由，v8 伙伴队列也不是 Gateway 会话队列。只演示游戏信件，不发送外部消息。

### O2 · 更改地址的晚信

第一箱药已装船，随后来信更改下一箱的地址，访客又插入“以我的命令为准”。玩家先推进装船，实际见到一个已执行动作与一个尚未发出的行动。

- 玩家操作：在忙碌会话为后续消息选择 followup、兼容源 collect 或 interrupt / steer 的有限示范 → 保留每封消息的原始身份和请求号 → 在逻辑边界应用新地址 → 按正确人匹配回执。
- 因果与证据：同会话不会被两个请求同时改写；已开始的法器按明确规则结束，尚未执行部分才可调整。合并信息不合并授权；取消保留费用和已装船的箱子。不同会话的工作继续存在。
- 错误与恢复：误把访客并入有效委托，权限检查拒绝；错误取消只停下余下步骤，须实际卸回错箱并重建后续派遣。跟随全部旧地址虽然可能仍有回执，却无法满足真实收件目标。
- 需新增：有限消息运行实例、队列模式和逻辑边界。模式名称对应官方概念，游戏不复制实时流式时序或当前产品的所有并行批处理规则。社会映射是排队、公文变更和权限不可借用。

### H1 · 第二次开炉

奥伦要两次修复同型炉子，第一次结束后工坊换班。玩家先真实观察故障、运行修复并验收，再决定保存哪一个小事实与哪一段已经成功的流程。

- 玩家操作：将带来源的炉型 / 温度范围写入有限记忆 → 由实际成功调用编成流程 → 结束会话 → 开启第二会话读取新快照，并按需加载流程 → 在同适用条件的第二炉执行。
- 因果与证据：口头“记住了”不会产生持久项；只存小事实不能替代多步流程，流程也不自动带入所有工具结果。第二炉仍要观察适用条件并真实验收。记录复用前后调用与资料成本，不固定宣布必省某个比例。
- 错误与恢复：没实际写记忆或适用条件不成立时，第二次缺资料 / 流程停止。可重读再保存或改手动路径完成；不会让新人无条件背出上次上下文。
- 复用与新增：v8 有记忆与实调流程；要精确表现 Hermes 启动快照，需独立的会话记忆快照合同。游戏的跨会话外部材料没有更新模型权重。

### H2 · 还活在昨天的手册

双封炉替换了旧单封炉，正在运行的会话仍带着旧启动快照。缇娅请求修正手册，并解释为什么“已修订”后另一个旧会话仍会用旧刻度。

- 玩家操作：观察新型号 → 对照记忆来源和版号 → 修订事实、停用旧流程或更新适用条件 → 查看存储新版与会话旧快照 → 明确用实际检索回响补当前知识，或开新会话加载新快照 → 重新执行与检验。
- 因果与证据：修改存储不会原地更换旧启动块；实时记忆工具回响可以提供新版信息，但必须实际进入当前输入。开新会话不回滚炉子或补晶石。新旧两种炉型分别留有真实案例结果。
- 错误与恢复：沿用已不适用的旧流程实际失败并停止；现场炉子保留真实变化，修订经验后恢复。不得自动把一次幸运成功保存为对所有炉型成立的流程。
- 复用与边界：旧流程证据和来源可用 v8；快照需新增。复盘比较不同记忆进入上下文的时机，不说其他产品完全没有经验复用或纠错。

### N1 · 换芯不换通行证

鲁因的修桥工坊可使用两种言灵连接，审阅者只有读图权限，施工者另有法器与许可证。玩家先换一个兼容连接并提交一次只读请求，观察角色和通行证未自动改变。

- 玩家操作：分别选连接 / 模型适配、工作角色、操作权限 → 检查连接是否提供声明工具调用格式 → 分别验证审阅能读不能改、施工可以在范围内操作 → 交换连接而保持其他配置，比较实际轨迹。
- 因果与证据：更换连接不提升身份；选择主角色也不自行改变已存会话模型。对不支持当前调用合同的连接，错误发生在接口适配层，不用多发几次或加全部权限“修复”。
- 错误与恢复：只读角色换了另一个模型仍不能施工；切正确角色后若工具权限仍窄，继续明确拒绝。分别修正对应层，保留调用前后证据，再真实建桥和验收。
- 需新增：独立模型 / 连接适配配置和有限兼容检查，不能只给 `EvaluationCandidate` 换名字。A / B 都是教学适配器，没有真实品牌能力、价格或智力排序。

### N2 · 两代契约的桥

阿芙迁移一份旧工坊契约；部分旧配置仍有效，一项旧插件接口已变，另有宽允许规则放在窄拒绝之后。第一动作是在副本中运行“可读图”和“不可写库”的两条真实探针。

- 玩家操作：从有限契约片段识别可兼容项和需迁移接口 → 确认角色自有权限与父角色派遣范围 → 调整有顺序的 allow / ask / deny → 在同资源上实际执行允许和拒绝路径 → 以证据启用新配置。
- 因果与证据：最后匹配规则对这项声明资源生效，错误顺序真的会扩大范围；父角色不能用自身只读设置推导子角色必然只读。受支持的旧字段不强制改写；不支持的插件接口不能因重命名文件就工作。
- 错误与恢复：表面格式迁移但行为不一致，探针指出层次；调整对应字段或接口，重测新版本，确认拒绝路径不产生副作用。旧版本证据不批准新版配置。
- 需新增：有限有序三值权限及配置合同校验；不是整套 OpenCode 解析器。兼容事实来自 V2 文档，试炼不宣传“所有 V1 都不能用”。社会映射是制度迁移要看实际行为。

### P1 · 三齿轮的小钟

奥伦交来一个只有消息、法器和回执的可拆解钟。玩家第一步接上观察齿轮，钟读到“电源未连”，然后亲手决定回执怎样继续进入下一轮。

- 玩家操作：装配最小工具集合与反馈 / 停止边界 → 用当前已知字段执行观察、操作、验收闭环 → 在一个知识节点分支，分别尝试不同调查路径 → 查看当前分支提供哪些历史，最终现场复查。
- 因果与证据：没有反馈只能留下完成声明；没有停止条件会耗尽受限预算。分支恢复较早知识，不使世界回到较早状态；事件保存与当前上下文是两种视图。
- 错误与恢复：从旧分支携带过期尺寸，实际操作条件失败；重读当前现场并继续，不把会话树当时间倒流。可以用小核心直接成功，不因没装“大框架”而降胜率。
- 复用与边界：v8 已有工具、反馈和有限会话分支；若表现逐个 parentId 的树，需要新可视化 / 合同，不能假称现有简单分支等于 Pi 全会话树。此处不复现生成模型的内部计算。

### P2 · 受信的外来齿轮

一家可信工坊送来扩展包与项目 MCP 配置，齿轮能自动搬箱，也可接触装载环境内的居民账册。玩家先拒绝项目资源加载，观察这些扩展未激活；这不意味着已有法器的运行权限已被缩小。

- 玩家操作：分别选择项目资源是否加载、扩展工作范围与整个工坊 / 仅法器隔离方式 → 在声明的虚拟环境挂载必要资料 → 运行扩展实际动作 → 检查扩展所在执行域与账册可达范围 → 完成搬运并确认账册未外送。
- 因果与证据：信任加载让齿轮激活，不使其结果可靠；只把内置法器置于副本，宿主侧扩展仍在另一域。工作目录是发现入口，不是不可穿越围墙；测试会留下真实可达 / 拒绝证据。
- 错误与恢复：信任项目后给整套宿主资源，扩展实际触及不该触及的虚拟账册；停止扩展、重新限定挂载和执行边界，再以新配置重测。已发生暴露保留，不能改设置抹历史。
- 需新增：声明式扩展加载与明确执行域，游戏绝不运行任意 JavaScript、真实 shell 或 MCP 服务。复盘必须标明 Pi 当前有项目 MCP，并区分加载信任、内容信任、执行隔离。

### D1 · 装配会办事的工坊

奥伦保留几颗兼容核心、一个循环器、法器注册台和两种档案架。玩家先插上核心和法器，却发现没有循环器就没有下一步请求；补全模块后再运行真正任务。

- 玩家操作：从有限目录装配模型适配、循环、工具注册、上下文 / 事件记录、存储 → 检查必需依赖与接口版本 → 激活模块图 → 实际运行运输闭环 → 更换一个兼容模块，验证其他部分仍履行合同。
- 因果与证据：缺循环不发下一步，缺工具注册不能靠拥有法器图标执行，缺持久层不能承诺断电恢复；依赖检查与启动无副作用拒绝、成功工具事件和现场收件共同验收。
- 错误与恢复：不兼容 schema 连接明确拒绝激活，不制造半次运输；在已有运行任务时先停到安全边界再改装。另一组兼容装配可以完成同一目标，不规定唯一品牌式答案。
- 需新增：真实的有限模块依赖、接口及激活合同。模块种类的选择会改变可运行能力，不只是统一 `blueprint` 的装饰标签；不执行 Cordis 或真实插件代码。

### D2 · 换档案架的那一刻

阿芙在运输到一半时要换档案架，旧扩展还注册着一个重复回执监听。玩家首先切断模拟电源再恢复，看到已持久化的事件与尚未提交的显示动画有何不同。

- 玩家操作：在明确安全边界暂停 → 查真实请求 / 已执行结果 / 已提交日志 → 验证替代存储的事件合同和版本 → 卸载旧模块并检查注册清理 → 恢复已提交事件投影 → 接回原结果后继续未执行动作。
- 因果与证据：动画“已搬完”没有日志不成为模型历史；有已执行回执的请求不重新发货。卸载后旧监听不再接收新事件，存储改变不复制或丢失已发生世界变化。错配结果或未来格式明确拒绝。
- 错误与恢复：仅留 UI 文本或重复监听造成重复归档企图，执行器拒绝重复业务 / 奖励；保留原事件、修复模块组合后恢复。不能无日志凭空判断未知请求未执行，应复查物理状态或受限停止。
- 需新增：有限可替换日志存储和 scoped 注册生命周期；v8 单一确定动作日志、v3 幂等思路和 v9 版本报告可作基础，但冻结 reducer 不改。此处不声称完整重现真实预览项目的迁移和过程丢失规则。

## 内核复用与最小新增合同

既有机制可沿用并测试：世界 / 已知分离，固定工具费用与预算，来源与摘要，真实保存与流程，身份 / 单次批准 / 两域世界，私有伙伴任务 / 实例依赖 / CAS，隔离案例 / 三态量测 / 当前版证书。它们的版本保持冻结。v9 每策略最多 8 步、每场最多 8 案例和 8 量测 / 条件；试炼不靠无限步骤逃避资源设计。

以下是实施建议，尚未落类型。若需要扩展，放新内核版本及明确迁移中，不向 v8 / v9 已发布 reducer 偷加规则。最终字段须经引擎设计和实际参考路线收敛，不能把这里的建议当成已有 API。

| 新合同 | 必须真实持有的状态 / 事件 | 服务试炼 |
|---|---|---|
| 独立执行范围 / 批准策略 | 允许触及的虚拟范围与批准方式分开；批准绑定请求、身份、环境及版本 | C2，以及 P2 |
| 有限消息路由 | 原始认证来源、渠道 / 账号 / peer、确定 route、sessionKey、回复目标；每会话实际私有资料 | O1 / O2 |
| 有限入口队列 | 消息实例、顺序、模式、当前已开始 / 未开始调用、原始权限上限、取消与已执行回执 | O2 |
| 会话记忆快照 | 持久存储版、启动 snapshot 版、实际检索回响；写存储不自动改 snapshot，开新会话不回滚世界 | H1 / H2 |
| 独立决策 / 连接适配 | provider、model adapter、角色、工具与权限的分别配置；有限 capability / schema 检查 | N1 / D1 |
| 有序权限 / 兼容合同 | 对有限 action + resource 的 allow / ask / deny；支持旧字段、忽略告警与需迁移接口分开 | N2 |
| 声明式模块图 | 模块 id / 版本、依赖、提供 / 消费合同、注册作用域、加载信任、执行域与激活版 | P2 / D1 / D2 |
| 有限持久事件提供方 | 真实提交事件、序号、格式版本、纯投影、恢复游标与结果去重；UI 暂态另存 | D2 |

入口与扩展仍只接受内容声明的 ID 和有效记录引用，不接受客户端给出的 `world/passed/score/certificate`、脚本或“身份已核验”。所有状态由真实动作历史构建。拒绝动作返回原状态；配置、模块激活、证书或动画不能直接满足物理目标。案例执行与现场执行分流，trial / sandbox / host 三者如需同时存在，应先定义并测试域合同，不能靠改一个 `realm` 名字复用同一世界。

型号 / 接口模拟是声明式教学适配器，不复现随机语言模型输出。对同任务比较适配器时，固定种子、输入、目标和工具合同；分开记录模型选择与 harness 配置，不能把脚本作者预设的好策略叫某品牌更强。真实产品、源码、浏览器游戏三种“版本”分别记录。

## 手机操作与学习证据

每场只先开放此次有用的几项操作；常用路径是“选一件遗物能力 → 选目标 / 输入 → 查看范围与成本 → 执行 → 观察差异”。复杂路由和模块图以点选插槽完成，不要求拖拽；任意触控至少 44px，320px 能竖排。开始一分钟内必须有一项真实观察、派遣、试运行或探针，不能先读长篇七款简介。

展示三层并保留原字段：故事中实际发生什么；宿主、输入、法器和证据如何流动；产品官方机制与教学简化。当前未知字段中性标识；成本用实际费用事件计算；覆盖分母、已见案例和旧构筑明确显示。失败可以暂停、查记录、修改并恢复本委托，损失不吞掉其他章节进度。

每组第二场要有一个未见情境独立操作，而非复选产品特征。记录实际配置差异、真实拒绝 / 恢复、关键输入、调用和新验收；提示使用降低独立证据，不永久卡住剧情。同一材料复述、同关重打或两张同源报告不增加迁移证明。延迟重遇在后续陌生委托使用同一机制，不能把这 14 场自称已经提供完整间隔学习系统。

双产品比较最后允许玩家从七组已取得的部件选混合构筑，在运输锚点的多个代表案例运行并现场交付；这是组内对照台与后续终章的复用，不另计第十五个作者任务，也不直接给品牌分数。价值选择可以影响 NPC 偏好或结局，技术硬条件不随偏好变成可省略。

## 实施顺序与验收门槛
