# 第一章《熄火之港》：八个任务的剧情与玩法设计

本轮内容落在 `src/content/chapterOne.ts`（新增五关、十二条参考与恢复路径）、`chapterOneStory.ts`（八关剧情与六名 NPC 设定）。内核、界面与存档由对应模块接入；数据存在不代表已完成浏览器试玩或用户已掌握知识。主线用确定规则推进，未使用真实模型生成剧情或判定输赢。

## 港口的一夜与兼容路径

六条主线、两条可选支线。推荐顺序：

`harbor-light → warehouse-gate → tide-ledger → last-ferry → hollow-regent → after-tide`

实际解锁依赖：

- 灯塔无前置；仓库需要灯塔。
- 潮汐簿需要仓库；末班渡船需要潮汐簿。
- 旧首领仍只需要仓库，保留旧档正在挑战首领时的入口；新玩家也可以提前尝试。
- 回潮复查同时需要末班渡船、旧首领。
- 雾钟与沿街药灯都需要潮汐簿；支线不阻挡离港，随时可以回访。

旧 `harbor-light@1`、`warehouse-gate@1`、`hollow-regent@1` 的世界、动作、文字、版本、回放与通关证据不变。旧三关通关者继续完成潮汐簿、末班渡船、回潮复查即可完成六条主线，不必重打。三关试玩完成不会被重新解释为全章完成。

| 任务 | 玩法差异 | 最终依据 |
| --- | --- | --- |
| 熄灭的灯塔 | 装工具、连接供能、接反馈 | 灯实际发光并验收 |
| 门后的药箱 | 把依赖关系迁移到门闩与门 | 门实际开启并验收 |
| 两本潮汐簿 | 来源、时效、观察成本和试航折返 | 所挂航牌实际试航通过 |
| 最后一班渡船 | 装载与系固顺序；空船也会离岸 | 药箱系固且对岸接货 |
| 空言执政官 | 两个独立目标不能互相替代 | 东西引航台各有验收 |
| 天亮前的复查 | 运车触发回潮、旧证据失效 | 物资已送达且桥脚当前牢固 |
| 雾中的回铃 | 容量 2 的换装；两条不同成本路线 | 主钟或三铃取得雾后回声 |
| 沿街的药灯 | 两箱守恒、分配地点、半路恢复 | 诊室首批与余箱均真实交接 |

## 新五关的已编写规则

成本为游戏单位，不代表实际产品、模型或工具价格。规则按动作推进，切后台、暂停和读对白不推动潮水。每趟预算不会因配置、派遣、暂停、换装而补满；要恢复初始世界与整趟库存，必须明确重开该任务。

### 两本潮汐簿：记录有来历，也有有效期

世界初始 `oldLedgerRoute=north`、`ledgerAge=上一个潮次`、`currentSafeRoute=south`，三个事实分开保存。读旧簿 1 点只获取旧内容与日期；问鲁因 1 点只获取“刚涨过潮”的线索；现场量潮 2 点获取当前安全水路。挂北/南牌各 1 点。按北牌试航确实产生 `trialReturned=true`，通航仍为 false；按南牌试航产生 `channelOpen=true`，另需验收 1 点。

整趟 10 点。参考路线：问话 1 → 量潮 2 → 南牌 1 → 南汊试航 1 → 验收 1，共 6。恢复路线：旧簿 → 北牌 → 北汊折返 → 量潮 → 南牌 → 南汊试航 → 验收，共 8。北牌不是“错误选项按钮”，它会改变实际标识并使试航船折返。

成功后保留带失效标记的旧簿，或将现行牌放入口并归档旧簿。这是信息使用方式的价值取舍，不授予额外技术证据。

### 最后一班渡船：起航成功与交付成功不同

世界有 `boatAt`、`cargoLoaded`、`cargoSecured`、`cargoDelivered`。装载与系固要求船在本岸。起航仅把船移到对岸，空船同样能走；卸货交接还要求船在对岸、已装箱、已系固。召回未交付的船把它带回本岸，保留已发生的装载状态。

整趟 16 点。启航和召回各 2 点，其他动作各 1。参考：检查 → 装箱 → 系固 → 起航 → 对岸交接 → 系固验收 → 交付验收，共 8。空船误启航后尝试交接失败，再召回、装载、系固、重新启航并交接验收，共 12。失败会留下船在对岸的事实，需要付出返航成本。

玩家可调整目标优先顺序，但不能改物理依赖。成功后可以留临时求渡的位置，也可以约定班次与变更通知，两种选择都能形成不同的信任。

### 天亮前的复查：旧证明不会永久有效

世界有 `bridgeStable`、`cargoDelivered`、`tidePassed`。潮前扣紧旧桥板可通车；成功发送最后一车时，确定的一次 hook 使 `tidePassed=true`、`bridgeStable=false`，物资交付仍为 true。事件明确提示变化并撤销旧桥验收，但不会把新桥状态自动塞入伙伴观察。潮后需要按新潮位装撑架。

整趟 12 点，各动作 1 点。参考：看桥 → 扣板 → 旧验桥 → 运车触发回潮 → 再看桥 → 撑架 → 新验桥 → 验货，共 8。沿用扣板和旧验桥会失败；之后重新检查和撑架可恢复，共 9。最后验桥与验货可交换顺序，须在同一个最终状态都成立。

本任务用独立新 ID 承接旧首领后的危机，不给旧首领偷偷追加第三阶段。自然变化也需要应对，不把一切问题归于一个坏角色。若未来增加首领回归，应使用独立任务 ID；本轮不改旧场景版本。

### 雾中的回铃：有限容量与两条设施路线

工具仍只有观察、操作、验收三种，本轮没有重型手、轻巧手、远望镜等新工具名称。容量限制为 2，整趟仅 7 点；典型配置是观察+操作，完成设施后换成操作+验收。换装不补预算。

- 主钟：检查 1 → 拆卡梁 3 → 敲钟并等回应 1 → 换装验收 1，共 6。留下 `bellRoute=main`、`mainBellReady=true`。
- 岸铃：巡看三处 2 → 架三处各 1 → 沿线呼叫 1 → 换装验收 1，共 7。留下 `bellRoute=chain`、三只铃都存在。
- 误敲未拆卡梁的主钟要花 3 点（公开标注的 failureCost），可能使本趟无法完成；不是无限重试就能补回。已架一铃就呼叫的失败仅耗 1 点，补齐余下两铃并验收可在总共 6 点内恢复。
- 配装不禁止熟悉规则的玩家直接带操作+验收；这样的胜利是有效完成，但本关“独立操作”证据还要求真实换过工具组合且未用提示。自动策略不会凭通关被认定为独立掌握。

两路不是换文案：动作数量、成本、世界事实和留下的设施都不同。通关后选择的是向居民教报讯约定，或明确维护交接；不会在结算后把主钟改成三铃。

### 沿街的药灯：价值路线不能凭空造物资

初始两箱在仓库。共同动作先送一箱诊室；余箱可集中送诊室（2 点），或装上推车送码头。世界 `warehouseCrates + clinicCrates + dockCrates + (cartLoaded ? 1 : 0)` 始终为 2。操作前置条件限制每次转移，重复交付会报告不能重复记账，不产生额外物资。

整趟 12 点。集中路线：清点 1 → 首箱 1 → 余箱集中 2 → 两项验收 2，共 6，结果 `clinicCrates=2,dockCrates=0,supplyRoute=clinic`。移动路线：看车 1 → 首箱 1 → 固轮 1 → 装余箱 1 → 推车 1 → 码头交接 1 → 两项验收 2，共 8，结果 `clinicCrates=1,dockCrates=1,supplyRoute=mobile`。

不修轮也能推车出发，hook 会让它停在 `cartAt=midway`。箱子仍在车上，码头没有库存。半路固轮耗 2，再推到码头、交接、验收即可恢复。参考恢复路径包含一次过早交接失败与现场观察，总共 11 点。物资只是虚构补给，不教学真实用药决策。

成功后选择沿街告知晚归居民，或留下取用与补货交接记录。地点分配由真实操作确定，之后的价值选择不倒写箱子位置。

## 剧情、旗标与三层复盘

`chapterOneStory` 是 UI 稳定接口：每任务包含 role、opening、success、hint、rules、location、两个 people/workshop 选项、recap，以及可选 next、outcomes。outcomes 只在完成世界的事实与条件相等时追加，支线因此不会声称走了不存在的路线。富剧情数据另保存逐句说话者、失败点拨、NPC 信任与未来回应建议。

六名长期 NPC 为莫拉（守灯人）、缇娅（药师）、鲁因（渡船人）、阿芙（档案员）、岑（巡城人）、奥伦（钟匠）。第一章只使用前三名，后三名是后续章节角色规划。回声与执政官不计入六名长期 NPC。

- 所有当前 UI 价值选择在成功后发生，并沿用 people/workshop 存储 ID。早期草案中的支线“出发前选路线”界面本轮不实现；路线由玩家操作自然形成。
- 叙事旗标由完成关卡与最终选择派生，不修改引擎事实、预算或学习证据，不重复叠加分数。
- 信任描述 NPC 愿意交给玩家哪种事，不是一根善恶数值条。
- 成功反馈先讲港口发生了什么；系统复盘讲行动关系；技术复盘再映射到工具循环、上下文、来源、约束、验证。不会在第一次对话里堆术语。
- 富剧情中的下一章来信、NPC 回访与道具镜头属于后续呈现规划。当前最小落地是港口记录、具体信任说明、真实路线结算文字；没有实现的镜头不能标记完成。
