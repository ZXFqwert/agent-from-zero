# 第八章《镜面议会》：评价契约、真实目标与制度

设计日期：2026-10-03。本文是实施前设计；不表示 v9、八场任务、关卡路线、UI、存档或真人试玩已经实现。第七章的实际浏览器 QA 与发布由主代理继续处理。新内容只在 v9 契约确认后写入独立的 `chapterEight.ts`，不改已经冻结的前七章。

## 本章的核心操作

镜面议会的光屏全是绿色，居民却仍在等待箱子、灯光和安全的桥。它并不是拥有隐秘恶意的模型：系统按被交付的指标办事，而指标、案例、记录与真实目标之间留下了空隙。

玩家在这一章掌握四种会改变结果的操作：装配待评估的有限行动策略；选择真实验收项和不能越过的约束；安排有区别的测试情境；依据回执修正、补充信息或明确停止。测试必须真的运行工具并改变测试世界，不能靠选择某个名词或点击“评测通过”获胜。

每张绿色回执都回答一个有限问题：“这一版构筑，在这些条件下，满足这些检查了吗？”它不能自动回答“居民的任务完成了吗”“下一版也能完成吗”或“其他情况都不会失败吗”。正式交付仍回到唯一现场执行和验收，测试世界与城市分别保存。

## 故事结构与角色

七匠之桥开放后，回声、弥灯和砧舟把真实交接送进议会。议会却坚持以“报告齐全”记录所有事故。缇娅是本章主要引路人：她逐张清点居民实际拿到的箱子，邀请玩家把一份绿色报告拆成能检查的链条。

六名核心 NPC 在本章回到自己的具体问题：莫拉检查船是否实际看见灯；缇娅检查物资与生活需要；鲁因比较不同航路的合法取舍；阿芙保存案例来历并封存留出情境；岑要求失败和不确定性有明确交接边界；奥伦把漂亮的指标盘拆成一根根测量线。无需增加第七名万能教师。

主要伙伴与两协作伙伴保持人物关系。需要独立勘测的情境可使用弥灯，施工交接可使用砧舟，但 v9 首次评价机制不强求把身份、沙箱、协作、技能全部组合到每一场。已经学过的概念以真正有用的复现回来，不以增加按钮数量冒充深入。

本章首领“百全镜议长”由许多报告镜面组成。每面镜显示的分数都可以计算正确；缺失的居民、过期的构筑和没有测量的伤害被藏在镜框之外。破解它依靠改变测量与交付制度，而不是积累等级或回答定义题。

## 八场互不重复的任务

### 1.《盖章的人，收箱的人》——代理指标与真实目标

第一主线，建议 ID `stamps-and-supplies`。议会承认“盖章完成率”，缇娅承认箱子真的到了。第一分钟玩家运行一次可点开的“小码头试单”，看见流程分别产生标签、发送请求和真实收件状态。

可操作区别：一份策略只贴标签并出具报告，另一份策略观察收件地、执行搬运并复查。评价项可选择“报告已出”“箱子实际收到”“没有挪用居民的应急库存”。弱检查可以真的显示绿色，因为它确实测到了报告；绿色不会直接使现场收件或正式交付成功。

参考路线：选择实际搬运闭环 → 配置真实收件与库存约束 → 在试单中运行、查看工具链 → 把相同版本策略用于现场 → 验收居民实际收箱。

错误与恢复：运行只盖章策略和报告检查，看到绿色但箱子没动；尝试正式交付时得到明确的“尚缺实际收件证据”。补上闭环与收件检查，重新运行当前版本，再现场交付。玩家可以从第一次就选择正确检查，不强制先误信报告。

胜利证据：真实试验工具事件、当前版本收件检查、现场运输与收件。删除复盘和知识问答后，这些操作仍不可省略。

### 2.《三盏灯，一条红线》——验收组合与硬约束

第二主线，建议 ID `three-lamps-one-boundary`。三盏雾灯中两盏亮得很快，第三盏需要保持居民门禁。某种策略可以通过“先开所有门”迅速点亮所有灯，却破坏委托明确要求的边界。

可操作区别：玩家装配验收组合，分别检查灯塔、岸灯和巷灯的实际可见性，同时把门禁保持封闭作为不能用平均分抵消的硬约束。总分或部分通过可以用于比较，但不能把一次隐私/权限违约算成“另外两项做得好，整体通过”。

参考路线：选受限工具与正常点灯流程 → 以全部完成条件和门禁约束运行 → 在现场完成三灯 → 分别验收灯光与门禁。

错误与恢复：用只看成功数量的检查得到漂亮比例；或者宽权限策略真的开门后点亮灯。补齐硬约束、实际封门并修正工具范围；新策略要重新测试，修复后的现场也要重新验收。修改检查不能撤销已发生的开门。

本任务教验收逻辑：全部必要条件、局部比较指标与不能越过的边界各自承担不同作用，不只是再演一遍“有回执才算成功”。

### 3.《议会只在晴天开门》——案例覆盖与分布缺口

第三主线，建议 ID `sunny-day-ledger`。公开展示每天都在晴天、轻载、单收件人条件下举行。居民的实际任务还包含雾夜、满载和临时失联。

可操作区别：玩家安排测试案例，而不是单纯增加测试次数。重复轻载晴天案例会增加实际运行记录与成本，但不填补雾夜、边界负重或断联的覆盖格。不同案例使用不同的真实测试世界初始条件，同一有限策略在其中执行自己的步骤。

参考路线：选择正常、边界、故障三类案例 → 运行当前构筑 → 由真实回执确定哪一条需要补观察、重试或停止 → 修正策略后重新运行受影响的案例 → 在现场完成任务。

错误与恢复：只反复运行容易情境，随后第一次运行边界/故障情境暴露缺口；保留反例，调整流程并重新测受影响的类。可以先做完整覆盖直接通过，不能暗中改变案例让第一次一定失败。

覆盖是本作者定义的小情境集合，不能被描述成统计意义上证明所有分布都可靠。UI 说“这些情境有证据”，不说“安全率 100%”。

### 4.《没有称过的货箱》——未知、补证与受限停止

第四主线，建议 ID `unweighed-crate`。货箱外观相同，一部分重量可从清单读出，另一部分清单缺失。把“我很确定”写得再大，也不会生成箱子的重量。

可操作区别：有限策略可以按已经观察到的重量走正确搬运、补做称重，或者在称重入口不可用时停止并向有能力的人交接。未知值没有被 silently 填成轻载；自信措辞也不作为校准过的概率使用。

参考路线 A：先检查输入是否包含重量 → 能称重就实际称重 → 按回执选工具 → 搬运与验收。参考路线 B：在称重入口确实不可用的情境，保持货箱和居民安全，产生带原因、缺失字段与下一步负责者的受限交接记录；这是正确停止，不假称已完成搬运。

错误与恢复：轻载默认猜测在轻箱案例可以碰巧成功，在重箱案例会得到真实失败；将未知分支改为补观察或受限交接后，分别重新运行。不要把所有猜测写成必然失败，也不要把停止写成自动修好现场。

正式交付可接受“实际完成”或委托明确允许的“安全交接”两种结局，但必须检查各自不同的真实事实。若委托不允许交接，停止只能保住资源和边界，不能赢得交付。这项区别需要通过关卡条件展示。

### 5.《百全镜议长》——局部漂亮、整体失序的首领

首领，建议 ID `perfect-mirror-speaker`。镜议长拿出一份针对旧构筑的好报告，宣布两处仓库都在“最快发货”。同一车应急粮却被北仓先拿光，南侧居民在分数之外。旧报告、漏测南侧、只优化本地速度三种机制共同支撑镜甲。

第一层是版本：一项新工具或策略修改后，旧绿色回执仍在档案中，但不能作为新构筑的交付资格。玩家需明确当前构筑、当前验收契约和这轮案例，旧报告只作历史。

第二层是覆盖：公开镜面只放北仓容易案例。玩家把南侧缺货、共享库存边界和工具失联放入评价，真实反例使相关镜面裂开。

第三层是整体：两个局部“发出了箱子”不是整城供应成功。玩家把共享资源和两侧实际收件作为整体验收，调整分配、运输与失败交接；所有局部动作仍通过真实工具发生。

参考路线：从开始就读取实际库存与两侧需求 → 配置有总资源约束的策略与真实验收 → 运行包含两侧的代表案例 → 用当前版本在现场合理分配与运输 → 分别验收两侧及余粮约束。可以直接避免旧报告和局部指标陷阱。

错误与恢复：拿旧报告尝试批准新策略，被版本检查拒绝；只北侧通过而实际南侧缺粮；修正指标但先前北侧囤货已经发生，需要真实回收再分配。重测当前构筑与相关案例，再执行恢复动作和整体验收。不能靠改分数或点“重新评估”生成南侧粮食。

社会类比明确落在委托方、执行方、指标和资源的制度关系。首领不被解释为语言模型有人的贪婪、羞耻、欺骗欲或稳定自我目标。

### 6.《玻璃温室的陌生委托》——未知系统的独立迁移

迁移任务，建议 ID `glasshouse-audit`。离开城市仓库，来到以镜面记录植物状态的温室。现成统计“叶片看起来绿色”，委托真正需要活根、足够水与病株隔离。漂亮的假叶能提高显示数字，不能让植物活着。

玩家自行选行动构筑、验收项与代表案例。案例至少有正常幼苗、缺水边界、可疑病株/缺失记录，实际动作包括观察根区、受限补水、隔离、复查或明确交接。没有为玩家预填正确检查或完整策略。

参考解：建立对实际活根和隔离边界的检查 → 使用有来源的根区观察 → 对未知病株先补证或受限交接 → 运行不同情境 → 用同版策略执行温室现场 → 核验真正活株、水量和隔离。

恢复解：只优化绿叶报告导致测试假叶被接纳、或实际浇水超过边界；加入根区与资源检查，修正构筑，实际撤下假叶/回收多余水/隔离病株后再验收。已正确的健康区不被强制破坏。

独立学习证据要求未点提示，真实更改评估配置、代表案例、当前版本报告、未知输入处理、实际现场恢复/交付与最终验收。选择题或绿色总分只作说明，不发独立迁移。

### 7.《两条都能走的归途》——价值取舍与技术硬条件

支线，建议 ID `two-valid-homecomings`。鲁因可以选择短而陡的航路，或长而平缓的航路。两者在不同居民偏好下都合理。委托明确要求安全、每位乘客到达、预算不越界；舒适、较早到达和资源余量是可以比较的偏好。

可操作区别：两种构筑在相同代表情境运行，玩家从实际调用、资源、检查与现场结果比较取舍。允许用不同偏好决定航路和剧情后果；硬约束仍完全一致。较快路线不因分数高而获得忽略一位居民或打开私舱的权限。

参考/替代路线分别走两条真实可达航路，使用相同硬验收，得到不同的成本与居民反馈。恢复路线是先按单项速度指标忽略限载，收到真实失败后调整批次或改平缓路线，再执行与验收。

技术学习通过操作和证据评估；最后的居民偏好选择不被标成答对/答错，也不因为某种价值选项授予更高理解等级。城市制度不只有一个作者宣布的“最善良结局”。

### 8.《练熟的镜子》——重复测试、泄漏与留出证据

支线，建议 ID `well-rehearsed-mirror`。阿芙保存三张公开训练牌，又封好一扇留出门。只为公开牌写死的路线能反复拿满分；这并不证明它能处理新的收件地或工具故障。

可操作区别：玩家可以检查公开反例、调整构筑；然后封存当前构筑版本，再开启一项此前未看过的作者定义留出情境并真正执行。打开后，这项情境不再被宣传为未见；修改构筑后拿同一项反复测试，可以得到调试证据，但不再得到新留出证据。

参考路线：按信息与工具规则构建通用策略 → 封存当前版 → 首次运行留出情境 → 实际通过并现场交付。可以第一次成功。

恢复路线：公开牌专用策略在留出情境失败 → 查看实际工具与输入记录，补足泛化规则 → 用已经公开的反例重测、明确称为回归测试 → 再封存新版本并运行另一个尚未暴露的有限留出情境。案例池有限，用尽后清楚说明本组没有新的留出证据，不许重置把旧牌变成新牌。

这不是科学证明整个模型泛化性的小试验。它只把调参、训练样例、留出案例与回归检查的区别做成玩家能亲手操作的制度。

## v9 最小评价契约：交给引擎代理确认

引擎代理 2026-10-03 给出的收敛方向：`candidates` 声明有限 `{call, whenKnown?}` 步骤；`cases` 声明独立 `initialOverrides` 与明确提供的初始资料；`metrics` 通过真实 observation 入口量测一个字段；`criteria` 对 metric 使用 equals / atLeast / atMost；玩家选择 candidate、criteriaIds 与 all / any；run 后逐步 tick；`gate.caseIds / criterionIds` 决定正式证书；现场 `Operation.evaluationRequires` 需要证书及真实前置条件。下文是这一方向的玩法约束，不表示接口已经落到共享类型。

本章会优先用该小合同实现前七种主要机制。第八支线还要求封存、曝光持久性或等价的已见案例记录；若该合同暂不含这些字段，应先向主代理明确实现边界，不把普通重复测试改名为未见留出。所有初始资料若由 case 提供，必须在输入记录里明确显示其来源和字段，不可偷偷把全部 initialOverrides 当作策略已知。

### 评价不直接改变现场

建议新增 `ScenarioDefinition.evaluation`，只用于 v9。它声明有限候选策略、测试情境、检查项、覆盖要求和正式交付门槛。内容仍为数据；没有脚本字符串、任意评分函数、网络模型或从数值查表直接生成“成功”。

候选策略是有限行动适配器：工具步骤加明确的已知字段分支。分支只读取试验主体的 observed，不读取测试世界真值；未知必须有明确的补观察/停止分支。每个案例有测试世界初始值与可用资料入口，并使用同一套声明工具/权限/预算执行。实际世界判定前置条件，实际观察才送给策略已知字段。

同一个策略跨不同案例执行。每次运行记录输入、请求、真实结果、有限预算和终态，再根据实际终态做检查。不能在内容里直接写 `policy A on case B: score 100`；也不能为教授某条概念把首次运行硬编码成失败。

每个 run 有独立 case world，不修改城市 world、现场审批、协作队列、现场验收或任务完成标志。试验成功不是现场成功。正式交付通过当前版合格报告后，仍须实际执行现场工具或有限策略并逐项 verify。

### 版本、检查与案例的状态

最低需要保存：当前候选策略/构筑版本、当前验收契约版本、所选检查项、所选案例、每次 run 的版本绑定、原输入与工具事件、实际检查结果、覆盖类别和已暴露案例集合。报告留在档案里，配置改变后不被抹掉，但不再自动适用于新版本。

硬检查与比较指标分别显示。比较指标可以是实际晶石、调用数、被服务数量或已明确测得的延迟逻辑轮次。硬检查来自实际事实的有限比较，必须满足规定的组合；相互抵消的总分不能替代它们。

检查允许真值不明/字段未测的结果。未知不是 false 也不是 pass；玩家需补测试、缩小交付范围或按委托允许的受限交接操作处理。不要生成伪校准“90% 自信”；若未来真实模型提供概率，需要独立验证其含义。

重复同一案例不会增加覆盖类型或独立泛化证据。留出门曝光集合在重试和检查点恢复后保持，类似已有 lifetime hint：不能靠恢复到旧档把已经读到的答案重新包装成未知。若实现这一持久保证暂时超出 v9，可将第八支线留到 v9.1，但不可假称留出未见；主代理需要明确记录缺口。

| 装配候选策略 | 选择受限工具、观察/未知分支、有限步骤 | 校验只使用声明入口，增加 candidateRevision，旧报告不删除 |
| 配置验收契约 | 真正目标检查、硬约束、比较项 | 检查引用合法、有限，增加 contractRevision；弱契约可显示自己测到了什么，不冒充正式门槛 |
| 安排案例 | 选择公开情境及覆盖类别 | 不泄漏尚未运行的隐藏真值，重复不会制造新覆盖 |
| 运行案例 | 当前候选版在一个具体 case | 在隔离 case world 真实执行步骤、扣实际受限成本、生成逐项工具与检查事件 |
| 封存版本 | 把当前构筑与契约作为本轮留出候选 | 保存不可原地改写的候选快照，之后调整不修改已封存内容 |
| 开启留出 | 首次运行未暴露的有限案例 | 明确记录曝光与版本绑定；重放使用已有记录，不重新生成不同答案 |
| 正式交付 | 将当前版策略/工具用于城市 | 查当前有效报告与委托门槛，再实际执行；不把测试终态复制进城市 |

API 参数只携带已声明的 ID、记录引用和有限配置，不接收客户端填写 score、passed、world 或 report facts。运行事件建议使用 `evaluation-change`，阶段至少区分 configured、ran、checked、sealed、exposed、accepted/rejected；工具事件绑定 case/run、candidateRevision、contractRevision，不混入现场世界或其他任务的 callId。

正式门槛需要明确哪些检查与案例/覆盖真的属于委托，而不是由玩家任意删掉硬约束。删检查可以改变展示分数，不能使居民的不可协商要求消失。当前所选契约在每个要求案例也必须通过，额外勾选条件的未知或失败不能被最低委托要求掩盖。正式现场动作未满足证书门槛时无副作用拒绝；尚未满足条件的 `certify` 是合法的申请动作，会记录拒绝原因而不发证。仅结构性拒绝使用作者 `expectRejected` 元数据，剔除该元数据后才解析真实动作。

## 实施与版本边界

冻结 v1–v8，不为了新增评价改变旧 reducer。v9 若复用 v8 执行语义，可增加自己的 reducer/评价模块并通过版本路由；若直接组合伙伴，需要保持输入私有与草稿/现场边界。第一版无需假装已经支持所有身份/沙箱/队列组合。

`SaveEnvelope` 0.8 → 0.9 只迁移内容标签，前 56 场按冻结内核重放；v9 的报告、案例终态、配置版本、曝光和覆盖必须从真实动作历史重建，不能信任导入宣称。任何中断后的 run 要么是原子完成的有限执行，要么持久化明确游标；不能刷新就再发一轮动作或把 pending 变成 pass。

`AuthoredStep` 新评价步骤仍只解析实际存在的案例、策略、报告与封存记录。参考和恢复路线至少十六条；第四和第七任务有真正可通的替代解。旧报告、缺案例、过度依赖代理指标和版本不符必须有可观察原因与恢复操作。

## 手机玩法与表现

议会场景中的镜面分三层：展示数字、试验小世界、真实城市。点击某张回执，可以折叠查看“输入 → 请求 → 回执 → 检查”，世界动画用实际 committed 事件播放。镜面的绿色与居民场景不会被同一状态变量控制。

常用操作顺序是“选构筑 → 选验收项 → 选情境 → 试运行”。默认先展示一张可操作的小情境，案例与术语逐关开放。不要第一屏塞完整测试配置表、指标论文或多选问答。手机上每个配置步骤以点选卡完成，复杂组合回工坊处理。

失败先显示实际未满足的条件和它来自哪一条工具结果，再允许补证、修改构筑、重测或恢复。全绿报告过期时保留在档案，标出原版本，而不是删除历史让玩家怀疑规则改变。

不确定性在表现上是未照亮的资料栏，停止则保留箱子和清楚的交接灯；不是羞辱式“胆小”，也不是停一下就给全分。首领镜甲根据实际有效检查/覆盖/现场状态碎裂，动画不决定通过。

## 本章完成标准

- 每种候选策略的案例结果由真实观察/请求/执行/有限预算产生，相同版本与动作可重放；策略不能偷看隐藏真值。
- 弱指标可以算对却与真实目标不同；硬检查不能靠平均分抵消；缺失字段不默认为 pass。
- 正常、边界、异常案例确有不同输入与执行后果，不只是换名字；重复不会加覆盖，旧版报告不会给新版交付。
- 修改评价不能撤销现场变化，测试不能复制结果到现场；两种合法价值路线都真实可达，不以作者道德偏好评知识。
- 留出曝光与提示历史在重试/检查点恢复时保持；如果未实现这项保证，明确记录未完成，不制造“新情境”证据。
- 每场无错误参考及同委托内错误恢复真实通关，正确首轮路径不被教学剧情强制失败；陌生温室独立操作与提示路线分开记录。
- v9 存档、旧 56 关兼容、案例中断/重放、篡改报告/版本/曝光拒绝、离线恢复与手机窄屏真实检查通过。
- 编辑试玩记录软件正确性和玩法问题；目标时长、真人乐趣、掌握及实际 iOS/Android 结果仍需分别验证。
