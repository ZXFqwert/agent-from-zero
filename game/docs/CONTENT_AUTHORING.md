# 内容编写与验证

当前规范对应 v0.7 前六章，共 48 个任务。新增章节须同时登记剧情、解锁图、参考路线与 chapter-packs.json。配置描述世界，不能直接执行脚本，也不能由动画宣布胜利。

## 关卡与规则

`src/engine/types.ts` 定义 `ScenarioDefinition`；`src/content/chapterOne.ts` 是实际示例。每关声明 ID、版本、初始世界、可观察字段、操作前置条件与效果、实际完成条件、概念和资源限制。固定效果关使用 v2；协议关使用 `engineVersion: 3`。`world` 是现场事实，`observed` 只接收已经执行的观察、已接通的回执和验收；策略不能从世界事实偷读答案。

- `cost`、`failureCost`、`verifyCost` 都是公开游戏能量。失败成本由实际前置条件决定，不能将它当作预先泄露隐藏事实的信号。
- `missionBudget` 是整项委托资源，`blueprint.budget` 是一次派遣上限。重新派遣和换装不补充整项资源；重置同时恢复世界和资源。
- `toolCapacity` 限制同时装备的法器。反馈、验收回路可以保留，但当前未装备的工具不能执行。
- `hooks` 是一次性的确定事件，支持指定调用后或成功操作后触发、条件、效果和环境/不可信报告。真实变化会撤销相关旧验收；不可信报告不能成为伙伴已知事实。
- `goals` 必须同时符合实际世界与有效验收证据。`goalOrder` 只改变策略处理先后，不能删除完成条件。
- `transferRequirement` 指定成功的玩家手动操作或实际执行之间的法器换装。未用提示且有对应操作证据，才记录独立决策；它不证明真人已经理解。

旧三关的 v1 内容及 `legacy-v1.ts` 已冻结，用于旧存档和历史回放。不要改写旧规则或事件文字后还声称相同版本可重放。更改规则需新的关卡/内核版本以及明确的迁移策略。

## 剧情、进度与表现

`chapterOneStory.ts` 与 `chapterTwo.ts` 提供逐句对话、NPC、价值选择、三层复盘和根据实际世界条件显示的结局。选择的关系回应由 `narrative.ts` 和 `CityLedger.tsx` 展示；支线的服务地点必须来自搬运后的世界事实，不能用结算按钮追认已经执行的路线。`progression.ts` 用前置依赖图开放任务，支线不阻塞主线，旧首领访问权保留。

世界值使用普通布尔、数字或字符串；中文显示放在 `presentation.ts`，技术回放保留原值。新增美术需在 `Scene.tsx` 实际预载并依据世界状态切换；文字不烘焙进图片。PNG 原稿不发布，公开 WebP 放在 `public/art/`，来源和转换记入 `ART.md`。

## 参考解、错误与恢复

每个新关都写可执行的参考路线和至少一条错误后恢复路线。存在合理替代构筑时也要单独记录。`chapterOneWalkthroughs` 分阶段声明装备、实际调用、预期消耗、中途世界与失效证据，最终必须真实获胜。请通过实际错误制造资源/证据问题，不安排“无论怎样都会失败”的教学脚本。

```powershell
npm run validate:content
npm test
npm run build
```

内容校验检查普通数据、字段与引用、依赖图、故事关联、官方档案元数据、美术预载，以及 93 条参考/替代/恢复路线；通过固定 reducer 执行路线并核对状态与消耗。构建会先执行该校验。

外部内容包用 `npm run validate:content -- --json path/to/bundle.json`。必须是含关卡、依赖、故事、NPC、档案和路线的完整内容包；只解析 JSON，限制 8 MiB，拒绝函数、getter、特殊原型、危险键和循环，不执行外部代码。此入口仍使用已实现的关卡机制约束，不是任意第三方关卡插件。

档案需核查日期、文档版本或源码提交、官方来源和教学简化。验证器只能核对网址归属与数据完整性；发布新产品结论前仍需阅读官方正文。实际手机试玩、乐趣、迁移学习和整季时长不能由内容校验或自动通关代替。

## v3 工具协议

`protocol.parameters` 指定类型、必填、范围、枚举和界面选择；`defaults` 可以故意错误，但正确输入必须可以直接成功，不能安排必败剧情。`variants` 只声明参数条件、事实效果、整数库存变化和数量保护，不运行任意代码。数量更新原子执行，负库存拒绝；错误请求有公开通信成本，非法动作/错误配对则被整体拒绝而不扣资源。

每次调用分配新的 `callId`。`delivery` 可为立即、待归档或第一次成功后丢失；未送达的物理结果不进入伙伴上下文。玩家 `receive` 必须匹配真实回执编号；自动收录能完成世界任务，但不能冒充独立手动配对。`receiptCount` 按成功的不同操作计数，不按反复点同一操作计数，且使用提示不会获得独立迁移标记。

业务凭证另由 `requestKey` 指定。游戏执行器只保存已成功业务的指纹（操作 + 保留类型的参数）和原回执；同键同请求不重复执行，同键不同请求冲突。新调用仍消耗通信资源，旧回执也可能过期，必须另做现场验收。这是本游戏的执行协议，不能说成 LLM、Chat Completions 或 HTTP 自动提供了这个保证。自动构筑中的固定凭证按本关操作编号生成；一个操作在当前委托中代表一笔业务，多笔业务需另设计身份与策略。

`toolArguments` 在工坊存储确定参数，自动策略才能使用；这不是模型权重训练。继续保留冻结 v1/v2 的行为与历史事件。v3 的规则变更也须新版本和迁移，不可改完后假装旧轨迹仍然相同。

## 分章资源

`chapter-packs.json` 声明共享图片和各章图片。生产构建检查身份、资源存在与所有公开图片的归属，内容校验检查每个已制作章节都有分包、每关主场景位于正确分包。程序/界面共享，各章场景精灵分别下载；Phaser 只预加载当前章节的纹理。每包分别存储完整标记，逐项核验字节数与 SHA-256；部分下载失败不能擦除其他章或旧版本。更新继续由安全检查点显式激活，不在安装时抢占任务。


## v4 回路与第三章

已发布的 v1/v2/v3 保持冻结，新场景声明 engineVersion 4。blueprint.loopPolicy 的 maxCalls 为本次派遣请求上限（1–64），maxRetries 为短暂故障的额外重试（0–8），permanentFailure 选择 stop 或 repair。能量、调用次数与重试不是同一个计数；总能量不得通过重新派遣、换装、刷新补充。

操作 failureKind 默认为 permanent；temporary 可配 retryWindow（attempts、readyFact），用于明确写在现场规则中的冷却装置。窗口就绪只改变世界并产生未交付的环境事件；下一次观察或工具回执才改变伙伴的知识。永久故障需要停止介入或按已收到的前置条件寻找修复动作，不能靠偷偷改世界让它成功。

控制器记录 dispatchCalls、各操作尝试/失败次数、最后交付的失败与停止原因，均参加严格重放。配置和重派可以明确开始新轮；暂停/继续保留当前轮计数。成功验收优先于耗尽，未成功且能量归零时优先报告能量停止。自定义故障字段不得用于旧内核。

参考路线 stages 可声明 loopPolicy；它必须经过同一蓝图校验。新增章必须注册剧情、解锁依赖、所有目标事实、独立离线包和 Phaser 纹理，并提供 reference 与 recovery 路线。第三章已有 16 条，详见 CHAPTER_THREE_QA.md。不要把正确参数、临时故障和需要修复条件的故障混为一类；提示、剧情与可见规则必须一致。

历史证明从旧版信封迁移到 season-0.4.0；旧版不能夹带当时未发布的章节。引导重打可更新当前进度，但不能抹掉先前更强的独立迁移历史，也不能再次发放契约数量。


## v5 文档上下文与第四章

已发布的 v1–v4 内核保持冻结。新文档场景声明 `engineVersion: 5` 与 `contextCapacity`（1–16 格）；格数是公开的教学单位，不是实际 tokenizer。每条观察有 `document.units/source` 和可选 `summaries`。摘要只从该观察保留字段，不能生成新字段；原文快照永久留在当次委托档案中，摘要可以切换、展开，但装入后的总容量不能超限。

读取资料产生有来源、读取事件与当时事实的 `ContextRecord`，不自动加入 `observed`。`context` 动作明确 include/exclude/summarize/expand，容量不足的动作整体拒绝，零副作用、零消耗。策略只读取选中的文档及一个独立的最新工具回响；新回响替换旧回响，历史日志不因此消失。此教学简化不意味着所有真实产品都只有一条回响，也不代表模型权重训练。

`operation.contextRequires` 是装置从当前卷轴提取的输入约束，独立于 `requires` 的现场前置条件；`contextMatches` 要求输入与现场当前字段一致。后者只能由执行器检查，规划策略不能偷读世界。输入缺失/过期会产生收费的真实拒绝，但不会把正确秘密值注入回声上下文。环境更换口令后，旧文档保持旧快照；必须重新读取并选择新文档。

路线的 stages 允许 `contextChanges`，按观察 ID 找最近一次实际读取的记录；每次改卷后仍用统一 reducer 执行。切换新旧版本、检查点、重试和重复奖励均严格重放。迁移任务可以要求特定文档、摘要和成功手动操作，使用提示不授予新的独立迁移；较弱重打不能抹掉此前更强历史证明。

当前 v5 不组合 v3 延迟工具协议，非法组合在内容入口拒绝。后续混合构筑要实现并测试新的组合内核，不能让内容字段看似存在而静默不执行。v0.4 信封仅能携带当时前三章；迁移到 season-0.5.0 保留所有原动作与证明，不自动发放新章节胜利。


## v6 记忆、会话与技能

新任务声明 engineVersion: 6、contextCapacity 和 memory。slots 限定可保存的实际观察来源；initial 明确旧经历来源和当时值，可以与当前世界不同。保存/修订只接受已取得的原资料，摘要仅保存保留字段；旧版本停用保留，recall 生成带 origin 的新副本，仍须 include。memoryRequires 要求装入当前有效版本的检索副本，不能用旧已停用快照蒙混。

session 动作 fresh/fork/switch 分别创建空上下文、复制已收材料、恢复已知会话。世界、权限、预算和当前调用次数独立；最多八段。sessionRequires 可以要求转换次数、初始 activeId 或 activeKind，来源从动作历史推导而非标题。暂停保留工具队列；切换会话取消尚未执行的队列，既有副作用保留。

skills 是有限、数据声明的固定虚拟工具配方；applicability 仅从已收到的上下文匹配。save 必须有按次序实际成功的对应最近调用；run 不执行副作用，只建队列。每一步走原执行器，权限/输入/预算照常检查；失败停止，手动工具动作取消剩余流程。skillRequires 可以要求物理 reset 操作之后的完整新执行。初始 NPC 旧流程与玩家实际学得流程分开记录。此处没有权重训练。

路线 stages.steps 支持 tool/context/memory/session/skill/step 的声明式交错；解析器只能引用实际读取记录和已知会话，不能生成事实。旧 calls 路线保持原行为。每个新任务仍须参考解与明确中间失败状态的恢复路线；v0.5 仅迁移信封，六代内核共同严格重放。v6 暂不组合延迟工具协议；跨委托共享档案未开放，不能在剧情或验收中声称已有。


## v7 来源、身份、单次审批与沙箱

第六章声明 `engineVersion: 7`、`contextCapacity`、`memory` 与 `security`；没有档案或技能时使用空声明，不能省略内核需要的结构。`security.principals` 最多八个身份，每项声明 `id/label/registryObservationId/credentialFact/grants`；不需要身份的资料指令任务可以是空数组。`grants` 只引用明确的操作 ID，身份原件须对应 `provenance: 'registry'` 的观察及其凭证字段。`security.sandbox: true` 才开放镜砂沙箱。

### 资料的宣称与来历

| 字段 | 编写含义与边界 |
|---|---|
| `observation.reportedFacts` | 覆盖这份资料宣称的值，不改世界；仅能使用该观察已声明的字段和有限的普通值。可用于伪造凭证或错误报告。未覆盖的字段读取当前执行环境中的实际值。 |
| `observation.provenance` | 作者声明的来历为 `registry` 或 `external`，默认 `external`。它与供玩家阅读的 `document.source` 字符串分别保存，抄相同标题不会改变来历。 |
| `observation.directiveOperationId` | 资料附带的行动指示，引用已有操作；用于展示资料怎样被错误提升为命令，不能执行任意代码。 |
| `SourceProvenance` | 实际记录观察 ID、来历、读取环境和可选行动指示。工具回响由执行器标为 `executor`；来历标签本身不保证内容真实、当前有效或具有职权。 |

读取仍只进入档案，必须装入本轮卷轴才能成为伙伴已知材料。保存、检索、摘要、会话分支与重试保留原有来历；摘要不能将外部来件变成登记原件，持久存储不能制造身份。检索记忆会增加 `origin`，即使保存的是登记资料也不能直接用于重新核验身份。沙箱读取的登记记录亦不能替代现场原件。

`blueprint.instructionPolicy` 默认为 `data-only`，仅使用任务数据；`follow-documents` 是明确开放的错误策略实验，自动策略会对本轮携带且尚未跟随的资料指示提出一次操作请求，并记录策略提升事件。两者是教学决策适配器，不是语言模型内部计算的复现。玩家手动请求及该错误策略仍经过同一执行器；`data-only` 也不是现实提示注入防护的保证。

### 请求者、职权和一次请求的批准

`security.authenticate` 必须引用实际读到、当前携带的现场登记原件，其凭证字段仍保留且等于当前现场凭证。自称身份、旧凭证、记忆副本和抄写来源均不能通过。成功核验只记录是谁；若环境事件换证，旧身份不会自动更新。

操作的 `security` 可分别声明下列规则：

- `principalIds` 限定可执行身份；身份还须拥有对应 `grants`，两项独立检查。蓝图的 `permissions` 或 `toolPermissions` 也仍生效，全部目标权限不扩大岗位职权。
- `approval: true` 要求先 `preview` 再 `approve`。预览只展示作者声明的预计写入，不执行也不宣称会成功。批准绑定操作、身份凭证、执行环境与当前环境版本；每张许可仅用于一次实际执行尝试，物理失败也会消耗许可。改目标、换凭证、换环境或改变相应世界版本须重新审阅；读取和验收不会凭空改变环境版本。
- `trustedInputs` 针对实际选用的每个字段检查来历与当前环境，其他可信卷轴不能替该字段作证。它独立于 `contextRequires/contextMatches` 的值与时效检查；可信来源仍可含过期值。
- `liveOnly` 拒绝沙箱交付；`sandboxRequires` 要求本次重试周期中相应操作有真实成功的沙箱回执，不能用尝试次数、上次委托或失败实验代替。

v7 当前只审批固定的 `operate` 请求，预览仅含 `tool/operationId`；不与 v3 参数/延迟回执协议组合，不接受额外参数或请求键。不能通过内容宣称支持尚未实现的带参数审批。操作 ID 唯一映射到目标和固定效果，因此本版本的批准范围是该固定操作。

非法或无权限的玩家手动工具动作返回原状态，零资源消耗、零许可消耗、零副作用；自动策略遇到同一边界会记录拒绝并停下来，亦不执行、不扣资源。结构合法但核验失败或签发失败的安全动作会记录失败反馈，这不等于工具已执行。明确区分预检拒绝与执行后的收费物理失败。

### 两个执行环境与学习证据

现场与沙箱分别保存世界、环境版本和验收证明。沙箱初始为任务起点副本，不在切换时复制现场；切换不补资源，不迁移副作用或成功证明，并取消未执行技能队列、最新工具回响、旧预览和故障续行状态。环境事件只作用于现场；会话分支共享世界，不能冒充沙箱。沙箱验收通过不能获胜，现场全部条件与现场有效验收才决定任务完成。

编成流程要求最近的实际成功调用来自同一个执行环境；流程执行记录也带环境，沙箱流程不能满足现场的 `skillRequires`。重试恢复起点世界和资源，清除当前身份、许可、两域验收和执行证据，保留持久资料来历及已学流程；已经发生的历史奖励仍由进度层去重。

陌生任务的 `transferRequirement.security` 可要求 `authenticatedPrincipalIds`、`approvedOperationIds`、`sandboxOperationIds` 和 `dataOnly`。分别核对成功核验、带有效许可的现场成功结果、沙箱成功结果及最终资料策略；原有 `operationIds` 还要求玩家手动执行的现场成功结果。它们与本次提示使用、资料装卷等既有条件一起决定 `independent-transfer`。仅点批准、仅完成沙箱或反复刷原关不授予新迁移证明；这些软件记录仍不证明真人已经理解。

`stages.steps` 增加声明式 `security` 动作：身份核验用 `principalId/observationId`，预览用固定 `call`，批准不加参数，环境切换用 `realm: 'live' | 'sandbox'`。路线解析器从实际材料解析记录 ID，优先当前携带的匹配记录；这也允许恢复路线刻意测试被装入的伪造纸或记忆副本，不能替玩家凭空读到真原件。每关分别编写参考解和可见错误后的恢复解；第六章有 16 条路线。

冻结 `legacy-v1.ts` 与 `v2.ts` 至 `v6.ts` 及原 `memory.ts`，v7 记忆扩展独立放在 `memory-v7.ts`。`season-0.6.0` 迁移仅更新存档信封，旧内容八类容器均限制在前五章；旧动作和事件不改写，七代状态共同严格重放。新的来源、权限、许可或沙箱规则变更须发布新版本并说明迁移，不能改旧 reducer 后继续宣称旧轨迹相同。
